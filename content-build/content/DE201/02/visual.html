1. Two Layers Of Shrink

Row vs Columnar Layout bought you the right to read fewer columns. Now watch a single column shrink twice: an encoding that knows what the values are, then a codec that only sees bytes. Step through it. Like packing: fold the clothes first, then vacuum-seal the bag.

Order matters and so does the division of labour. Encodings do the intelligent work — they are type-aware and reversible and they exploit what the values are. The codec is general-purpose and sees only bytes, so it mops up residual redundancy in whatever it is handed.

2. The Cardinality Cliff

Dictionary encoding is not a setting that always helps — it has a cliff, and the writer walks off it silently, mid-chunk. Drag the number of distinct values. Like a phrasebook: brilliant for 200 phrases, useless when every sentence is new.

Nulls: honest, or a sentinel?

For sorted numerics there is a third encoding worth knowing: DELTA_BINARY_PACKED stores successive differences instead of absolute values, which shrinks magnitudes dramatically on timestamps and auto-incrementing ids. Visual 5 is about why that will look extremely familiar.

3. Sorted Pays Twice

You sorted at write time to make min/max pruning work. Here is the second dividend from the same decision, on the same data. Toggle the order. Like tidying a bookshelf: it makes finding a book fast and it makes the shelf take less space.

Two separate mechanisms, one write-time decision. Sorting narrows every row group's min/max so predicate pushdown can skip whole groups from the footer alone — and it lengthens the runs so RLE collapses the indexes to almost nothing. Neither is a query-side tuning knob.

4. Where The Bottleneck Is

Heavier compression is not better or worse — it is a trade of CPU for bytes, and which side wins depends entirely on what is currently the slow part. Move the storage and watch the answer flip. Like posting a parcel: worth repacking it smaller if postage is expensive, not if you are walking it next door.

The asymmetry that settles most of it

And choose per temperature, not once for the estate: hot, interactively queried tables want Snappy or low-level Zstd; cold archival partitions tolerate high Zstd levels where a one-time compression cost amortises over years of storage. Parquet even permits a codec per column, which matters when one bulky text column sits beside a dozen numeric ones.

You already compress sorted integers for a living. Put the inverted index beside the Parquet column and the transform is identical — only the vocabulary differs. Tap a row. Like discovering two trades use the same tool under two different names.
