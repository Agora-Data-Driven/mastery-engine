1. The Missing Layer

Consistency and Atomicity Limits of Object Storage ended with a prescription: immutable objects plus one authoritative reference, swapped conditionally. Here it is, built. Tap each ACID letter to see which layer supplies it. Like a library: the shelves hold the books, the catalogue decides what counts as the collection.

Physical structures differ — Iceberg commonly uses snapshots, manifest lists and manifests; Delta records ordered transaction-log actions plus checkpoints so readers do not replay an unbounded log. Both make logical membership explicit and reconstructable, and both need metadata maintenance alongside data compaction: rewrite oversized manifests or add checkpoints based on measured planning cost.

2. Walking The Chain

Every commit leaves an immutable description of the table behind it. Pick a snapshot to read as-of, then expire some history and watch a pinned job break. Like a photo album: each page is a fixed moment, and throwing pages away is not the same as tidying up.

Snapshot inspection is also a debugging tool: a sudden row-count change traces to the commit that added or removed particular files. Operation summaries help and should not replace independent validation of schema, counts and business measures — the summary says what the writer intended.

3. Safe Or Breaking

Schema evolution changes columns without rewriting history — and whether a change is safe depends on how the format identifies a field and on what readers expect. Send each change through, and switch the reader. Like renaming a person in a database: fine if you kept their ID, chaos if you keyed on the name.

Expand and contract is the migration shape for anything breaking: add the new field, write both old and new forms, backfill, validate, migrate readers, stop writing the old field, then remove it after the compatibility window. Contract tests across all production engines catch the assumptions that one table client alone hides.

4. Backfill Without Mutating

A backfill recomputes history after logic, schema or source truth changed. Done safely it is the same publish-by-pointer move, at scale. Step through it. Like reprinting a book: you set the whole new edition before anyone is asked to swap their copy.

Very large backfills: the coherence problem

Rollback is a metadata operation: retain the old snapshot, monitor queries after publication, and switch back to a known state if guardrails fail. No terabytes are copied. Garbage collection waits until the rollback and active-reader windows expire.

5. The Atomic Alias

A search index rebuild is the same mechanism with different nouns. Build the new generation privately, validate, move a small pointer. Then handle the part people forget: where the writes are going. Like a shop moving premises: the sign redirects customers, and the deliveries need redirecting too.

Write routing: four ways, each needing an idempotent sequence position

Table snapshots and index aliases express one durable principle: build immutable state privately, validate it, then publish by changing a small authoritative reference atomically. That separates expensive construction from the visibility boundary, and it makes rollback a metadata operation rather than an emergency rebuild.
