1. Two Clocks Running

In lesson 2 you learned never to file a row by the date the job ran. Streaming makes that split visible: every event carries two timestamps and they drift apart. Drag the network delay. Like a postmark versus the date written inside the letter.

EVENT TIME — in the data 10:07when it happened. Immutable, travels with the record.
PROCESSING TIME — the wall clock 10:08when you saw it. Depends on the network, retries and your job's schedule.

This is the same rule as deterministic partitioning, one lesson on: the answer must be a function of the element, not of when the machinery observed it. Windowing on processing time is the streaming form of ingestion-date partitioning.

2. One Event, How Many

The same event at 10:07, under three window shapes. Notice how many windows claim it — that number is your state and output multiplier. Like a shift rota: fixed shifts, overlapping handovers, or "however long the shop stayed busy".

3. The Lateness Gate

The window [10:00, 11:00) closed when the watermark passed 11:00. Drag how late an event is, in event time. Like a shop that accepts returns for 30 days — after that, a different department handles it.

ACCEPTED — window state still alive
TOO LATE — dropped, quarantined or reconciled

A watermark is an estimate of event-time progress, never proof that nothing earlier can arrive — which is exactly why a late-data policy is mandatory rather than optional. And the pipeline watermark is limited by its slowest input: one idle partition can hold every window open.

4. Panes And The Sink

One window fires three times as events trickle in: 80, then 100, then 103. Choose what the pipeline emits and what the sink does with it. Like a running total on a receipt versus each item added separately.

Pane identity has to survive retries too: key it on business dimensions, window start and end, and a result version. A worker attempt ID changes on retry and turns one pane into several sink rows.

5. Where Once Breaks

A message is redelivered — because an ack was lost, not because processing failed. Follow it through four stages and see which ones the runner's guarantee actually covers. Like a signed-for parcel: the courier's guarantee ends at your door.
