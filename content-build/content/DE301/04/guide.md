**The big idea**: **Feature Pipelines: From Raw Events to Model Inputs** established that a model's inputs are manufactured in stages; **Point-in-Time Correctness and Time-Travel Joins**, **Label Leakage: Learning from the Future** and **Training-Serving Skew** established that a stage which quietly changes what a row knows is a correctness bug; and **Versioning Datasets Alongside Models** with **Reproducible Training Data: Snapshots over Live Queries** established that the only defensible dataset is one you can rebuild. Text is that discipline over messier raw material. A corpus becomes useful only after bytes are extracted, normalized, deduplicated, classified and filtered under reproducible rules, and **each stage changes what downstream models can learn and retrieve**. Separating the stages and recording their versions makes false removals, parser defects and distribution shifts diagnosable instead of irreversible.

**Key concepts**

- **Parsing reconstructs a document; extraction selects what downstream needs; chunking is neither.** Parsing converts HTML, PDF, office documents, email and code into a structured representation; extraction then selects text, headings, tables, links, images, metadata and source locations. Chunking — choosing retrieval units — is a later, separate decision. Collapse them and a parser upgrade silently rewrites your retrieval units.
- **Immutable source bytes are the input boundary; the parsed artifact is versioned output.** Record content hash, media type, source URI, fetch metadata, parser name, parser version, options and run ID, and emit a new parsed artifact rather than overwriting the source record. A parser upgrade then rebuilds descendants without pretending the original document changed — the snapshot-over-live-query argument, applied to bytes.
- **Format-specific work is where extraction actually fails.** HTML extraction must remove navigation, scripts, cookie banners and repeated chrome while preserving meaningful headings and links. PDF extraction must handle reading order, columns, headers, footers, page numbers, scanned images and tables; OCR adds its own model version, confidence and layout errors.
- **Source offsets are what make citation possible.** Normalized character positions may not map to HTML bytes or PDF coordinates, so preserve page and block identifiers, DOM paths, bounding boxes or span mappings. A plain text blob with no mapping cannot cite original evidence, however good retrieval gets.
- **Failure must be explicit: success, partial-with-warnings, or a quarantine record with an error class.** Silently returning empty text is the dangerous outcome, because it looks exactly like a valid short document and passes downstream unnoticed. Track empty rate and extracted-to-source-size ratios by format so a parser regression surfaces as a distribution shift, not a mystery.
- **Normalization is a versioned policy, not a utility function.** Unicode normalization, whitespace handling, line endings, hyphenation repair and boilerplate removal are judgment calls, and aggressive normalization corrupts code, identifiers and tables. Version policies by document type and retain pre-normalized output so an audit can separate parser errors from normalizer errors. Stage boundaries make this testable: golden fixtures assert extracted headings, page spans and exact text per parser version, and corpus-level canaries measure length distributions and failure rates before a new parser is promoted.
- **Exact hashes miss the duplicates that matter.** Reordered whitespace, templates, minor edits or an inserted banner change every byte, so a byte-identical test finds nothing. Near-duplicate methods build compact signatures approximating a similarity measure, letting a pipeline cluster variants before training or retrieval.
- **MinHash estimates Jaccard similarity as a fraction of matching components.** Convert each document into a set of shingles such as normalized word 5-grams; Jaccard is `|A intersection B| / |A union B|`. For each hash permutation retain the minimum hashed shingle — the probability that two documents share one component *equals* their Jaccard similarity. With **128 components, 102 matching gives `102/128 = 0.797`**. More components reduce estimator variance but cost storage and comparison time. Shingle size is the sensitivity dial: small shingles tolerate edits but overlap accidentally, large ones demand longer exact runs.
- **SimHash approximates angular or cosine similarity over weighted features.** Hash each feature to a bit vector, add or subtract its weight in every bit dimension depending on the hash bit, then set each signature bit by the sign of the accumulated coordinate. Similar feature-weight vectors have small Hamming distance. MinHash suits set overlap and containment; SimHash suits weighted bag-of-features similarity and pages differing by small edits.
- **Neither signature proves semantic equivalence, and containment is not symmetric.** Two contradictory documents sharing a template can look near-duplicate. A short article copied inside a long compilation has low symmetric Jaccard despite substantial reuse — compare containment ratios or segment the long document, and record the metric and threshold in pair provenance.
- **All-pairs comparison is the wall LSH exists to avoid.** Comparing every pair of N documents needs roughly `N*(N-1)/2` comparisons, infeasible at corpus scale. Locality-sensitive hashing places signatures into buckets so similar items are likely to collide and become candidate pairs; exact similarity is then computed only for candidates.
- **Banding turns a signature into an S-shaped threshold.** Divide a signature into b bands of r rows; two documents are candidates if all r values match in at least one band, with probability `1 - (1 - s^r)^b` at Jaccard similarity s. **With 20 bands of 5 rows, similarity 0.8 gives about 0.9996 and similarity 0.3 gives about 0.0475.** More bands with fewer rows increase recall and candidate volume; fewer bands with more rows increase selectivity and can miss true duplicates. Tune against labeled pairs *and* budgets.
- **LSH generates candidates; verification still decides.** A separate stage computes Jaccard, Hamming distance or another exact criterion. Buckets go hot on empty documents, boilerplate or repeated default pages — cap or special-case them, never discard silently: a huge bucket may be a real template family or a parsing bug producing identical empty text.
- **Incremental and distributed dedupe need stable identity.** New signatures are compared against existing bucket members, so when shingling or hashing changes you build a **new index namespace** rather than mixing incompatible signatures. Deterministic pair identity — sorted `(doc_a, doc_b, method_version)` — makes retries idempotent. Connected components can build clusters, but transitivity deserves review: A may resemble B and B resemble C while A is below threshold with C. Monitor candidate recall against a brute-force sample: a sudden fall signals incompatible signature versions, a huge rise signals boilerplate or empty extraction.
- **Canonical selection is a separate decision from similarity classification.** Keep the earliest source, highest-quality version, authoritative domain or richest metadata and link duplicates to it; never delete all but one before provenance is preserved. Purpose changes the acceptable error: training removes repeated pages to reduce memorization, while retrieval keeps jurisdiction-specific copies with identical wording and different metadata. Decide whether the unit is content, source record, document version or permission-scoped artifact *before* labeling a pair duplicate.
- **Language identification is a distribution with a confidence, not a bare label.** It routes text to tokenizers and models, enforces corpus scope and measures coverage, but short text, code, names and mixed-language documents are hard — store confidence and model version. Run it on representative content: boilerplate navigation can overwhelm the body language, and a title alone is too short. Section-level detection preserves multilingual documents that a document-level majority label would misclassify.
- **Quality filtering encodes value judgments, so it needs a funnel with reason codes.** Rules remove or downweight empty text, parser garbage, repeated characters, link farms, machine-generated spam, extreme symbol ratios, unsupported languages and unsafe content — each able to create demographic or domain bias. Record counts and retained bytes before and after parsing, exact dedupe, near-dedupe, language routing and every rule, and keep a sampled quarantine for reviewing false positives.
- **Thresholds vary by type or they erase whole subcorpora.** Code legitimately has high punctuation, mathematical text has symbols, chat contains short fragments, OCR contains unusual spacing — one universal alphabetic-character threshold deletes all four. Evaluate by language, format, source and length bucket. Classifier-based scores need calibration and drift monitoring: a model trained on polished articles rejects dialect and low-resource languages, so treat the score as one signal, not truth.
- **Filtering order changes results and cost.** Parsing precedes text-based filters; exact dedupe first reduces expensive model calls; quality models run after language routing; near-dedupe runs before or after quality scoring depending on whether canonical choice should favour the best variant.

**Rules to remember**

- Parsing reconstructs, extraction selects, chunking comes later. Three stages, three versions.
- Source bytes are immutable; a parsed artifact is a new versioned output, never an overwrite. Never return empty text on failure — emit a quarantine record with an error class.
- Cap decompressed size, page count, recursion depth and OCR time, and parse untrusted formats in isolated workers.
- Jaccard is intersection over union; the MinHash component match rate estimates it (`102/128 = 0.797`).
- MinHash → set overlap. SimHash → Hamming distance over weighted features → angular similarity.
- Candidate probability under banding is `1 - (1 - s^r)^b`. More bands buy recall; more rows buy selectivity.
- LSH produces candidates only. Verification is always a separate stage.
- Change shingling or hashing and you need a new index namespace, not a mixed one.
- Canonical selection is policy; similarity is measurement. Never let one imply the other.
- Store language as label plus confidence plus model version, and every filter with a reason code, a count and a retained-bytes figure.
- Change a threshold and you build a new corpus version, compare, then publish immutably.

**Common pitfalls**

- **Emitting a plain text blob with no offsets.** Retrieval works, citations cannot be resolved, nothing fails loudly.
- **Silent empty extraction.** A zero-length "document" is indistinguishable from a short one; only empty rate and size ratios expose it.
- **One universal quality threshold.** Punctuation-heavy code, symbol-heavy mathematics, fragmentary chat and oddly spaced OCR are all erased by the same alphabetic-character rule.
- **Reading a high similarity estimate as "same meaning".** Two contradictory documents on one template score near-duplicate; signatures measure form, not truth.
- **Using symmetric Jaccard for containment.** A fully reused short article inside a long compilation scores low and survives.
- **Treating LSH candidates as confirmed duplicates.** Banding has a deliberate false-positive rate; skipping verification deletes real documents.
- **Mixing signature versions in one index.** Candidate counts collapse and it reads as "the corpus got cleaner".
- **Deleting duplicates before deciding the canonical policy.** Permissions, language, timestamps and legal retention make two identical texts operationally distinct, and the delete is irreversible.
- **Trusting a quality classifier without per-group retention rates**, or **mutating the only corpus** when a threshold changes. Global allowlists that bypass every later check create permanent blind spots; scoped exceptions record owner, rationale and expiry.

**How to approach the questions**

1. Name the stage first. Parsing, extraction, normalization, exact dedupe, near-dedupe, language routing and quality filtering fail differently, and most distractors are a true fact attached to the wrong stage.
2. For a similarity number, ask which metric it belongs to. Fractions out of a component count are MinHash and Jaccard; bit distances are SimHash and Hamming.
3. For LSH questions, put the numbers into `1 - (1 - s^r)^b` before reasoning verbally, then check direction: raising r or lowering b makes the curve steeper and more selective.
4. When something vanished from the corpus, ask what the funnel's reason code was. If the design cannot answer, that *is* the answer.
5. Separate detection from action. "These two are similar" and "delete one" are different claims, and the second needs a canonical policy.
6. Watch absolutes. "Deduplication improves the corpus" depends on whether the consumer is training or retrieval; "the parser is better" depends on measured distributions, not on one fixed document.
