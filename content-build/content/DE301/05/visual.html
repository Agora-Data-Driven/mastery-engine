2. Rerun Without Duplicates

12 chunks, drawn from 3 documents. The first run died partway through. Drag how far it got, then choose what the job keys its writes by, and watch the re-run either converge or make a mess. Like re-photocopying a jammed print job: if the pages are numbered you reprint the missing ones, if they are not you print the lot again.

Retries only work if the request items are stable too. A timeout that fires after the service already processed the batch must, on repeat, upsert the same embedding IDs — so attempt status is recorded separately from committed artifact identity. And permanent errors (input too long, invalid encoding, unsupported language) belong in a quarantine with chunk ID, error class and model version, not in the retry loop, which would burn quota forever on input that can never succeed.

3. Packing The Batch

The endpoint accepts at most 20,000 tokens per call, and the queue holds chunks of 600, 900 and 1,100 tokens in rotation. Offer it some chunks and choose how the batcher fills the call. Like loading a lift rated in kilograms, not in people.

Two details that decide real batches. Reserve room for model-specific prefixes — an instruction prefix on every item is real tokens, and a batch sized to exactly 20,000 fails once one is added. And count with the exact tokenizer version: a batcher counting with last year's tokenizer is estimating, not budgeting, and the gap only shows up on the longest inputs, which are the ones already closest to the ceiling.

4. Vector Plus Metadata

A vector on its own is 768 numbers nobody can filter, cite, invalidate or explain. Switch a field off and watch which of those four powers you just lost — then choose where the fields live. Like a photo with the date, place and people stripped out: still a photo, useless as a record.

Cardinality is the quiet constraint. Filtering on tenant or language is cheap and selective; storing a huge array of individual principals on every vector is not, so access control is modelled with compact group IDs, partitioned indexes or a precomputed authorization token set — and reviewed against the exact query behaviour, not the intent. Watch the same monitors either way: orphan vectors, stale metadata versions, dimension mismatches, hits on inactive records, and catalog-versus-index count drift.

5. Pre-Filter Or Post-Filter

One shared index of 1,000,000 vectors. Drag how much of it the requester is allowed to see, say how many results they want, and declare whether the predicate is a security boundary or a preference. Like a bouncer at the door versus a bouncer walking guests back out afterwards — same list, very different evening.

Two things that survive every choice here. Filtering interacts with graph connectivity: in a graph index, eligible nodes are often reachable only through ineligible ones, so some engines traverse them and some prune them — the word "pre-filter" does not tell you which, and only the first preserves recall. And filtered recall must be measured against exact search inside the eligible subset, sliced by eligible-set size, tenant, filter combination, k and candidate budget. Global unfiltered recall predicts none of it.
