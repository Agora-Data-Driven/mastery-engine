1. Unbundling The Lake

Storage-Compute Separation and the Columnar Engine already split compute from the bytes. A lakehouse keeps going and splits off three more things that used to travel with storage. Flip the model, then tap a concern to see who owns it and what breaks when you confuse two of them. Like a house that used to be one room: the same living happens, but now the kitchen, the filing cabinet and the front door are separate places with separate keys.

This split is the whole exam skill for this lesson. Nearly every distractor in this domain is the correct service for a different concern — Dataplex offered where the requirement is query access, BigLake offered where the requirement is discovery, a copy pipeline offered where the requirement is governed distribution. Name the concern before you read the options.

2. Delegating File Access

A BigLake table's defining trick is that nobody but the connection needs a permission on the objects. Drag the team size, switch the model, then leave one direct bucket role in place and watch the policy stop meaning anything. Like a hotel safe: guests get a room key, one manager holds the master — unless somebody left a back door propped open.

Troubleshoot this stack layer by layer: a permission error can come from the querying principal, from the connection itself, or from the connection service account's object permissions — three different fixes behind one message. And note what BigLake never claims: it governs the table path, so auditing direct bucket roles is part of the design, not an afterthought.

3. The Metadata Cache

Before a byte is scanned, a query over object storage has to work out what exists. Drag the object count, switch the cache on, then set how stale its answer may be — the two dials pull in opposite directions. Like a warehouse stocktake: keeping yesterday's list makes you fast and occasionally wrong about this morning's delivery.

The cache buys discovery time, never scan time. Millions of tiny files, a non-columnar format or a partition column nobody filters on stay exactly as expensive with caching on — that is a job for Parquet, stable schemas and partitioning on the filters people actually use. Slow planning and slow scanning are different diagnoses.

4. Zones And Aspects

Dataplex gives distributed data a logical shape — lake, zone, asset — and hangs structured metadata on it. Pick the zone, then switch on the kinds of metadata this table actually carries and read the verdict a consumer would reach. Like a jar in someone else's kitchen: a label tells you what it is, a date tells you if it is still good, and a name tells you who to ask.

Zones are only governance when they carry different policies — eight zones under three distinct rules produce taxonomy, not control. And keep three tools apart: lineage names who is affected, profiling describes what the data looks like, quality rules decide whether that is acceptable. A glossary gives active customer a shared meaning; it cannot supply the agreement, which is an owner's job.

5. Copies Or Links

Every consumer wants the same dataset. You can hand out copies or you can publish a listing. Drag the number of consumers, switch the model, and change what is being shared — because a dataset and a Pub/Sub topic create different things in the subscriber's project. Like lending a book: photocopy it forty times, or give forty people a library card.

Zero-copy is not zero-governance: exchange and listing IAM decide who may discover or subscribe, row-level and column-level controls decide what a consumer sees, and a public exchange has a different risk profile from a private one. The counter-case is real, though — independent retention, offline access, an incompatible region or isolation from publisher changes all argue for exports.
