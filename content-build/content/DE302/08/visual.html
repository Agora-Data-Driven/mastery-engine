1. From Design To Operations

Lessons 01–07 built every box on this diagram: Pub/Sub, Cloud Storage, Dataflow, BigQuery, IAM, CMEK, Dataplex, an orchestrator. Flip the switch and the same drawing has to survive being attacked. Like a house plan versus the same house with smoke alarms, a stopcock and a spare key at the neighbour's.

Attack the diagram — what happens if…

A useful diagram tells a requirements story: producers → ingestion → storage → processing → serving → consumers, batch and streaming drawn distinctly, control planes around the outside, and projects, regions and trust boundaries labelled where they change the decision. Every arrow means a flow, an API call, a dependency or a permission — and the legend says which.

2. Impact To Cause

Three dashboard layers, read top down: who is hurt, which stage, which resource. Then one dial — how long impact must persist before anyone is paged — that decides whether the on-call phone is useful or ignored. Like a smoke alarm: too sensitive and someone takes the battery out.

Every alert must carry the affected resource, current value, threshold, runbook, dashboard and owner — and late data, partial quality degradation and complete outage deserve different routing and urgency. Quality checks belong beside infrastructure checks: recorded as a time series, a null rate drifting 0.2% → 1.8% → 4.1% is a slope you can act on weeks before it trips anything.

3. Where The Money Went

A bill that doubled is not yet a problem — or a defect. Split it three ways and the answer names itself. Then watch a quota failure get worse the harder you retry. Like a bigger grocery bill: more mouths, higher prices, or a hole in the bag.

Budgets notify; they do not stop spend. And the failing quota belongs to the consumer or quota project, which is frequently not the project storing the resource — the most common wrong turn in quota triage. Troubleshoot symptom → orchestrator → first failed stage → service error → recent changes, and preserve run IDs and logs before anyone reruns.

4. Idle Or Waiting

A persistent Dataproc cluster bills 24 hours a day; an ephemeral one bills only while it works but pays ~90 seconds of creation per job. Drag the workload and watch which waste is bigger. Like owning a van versus hiring one: the question is how many days a month you drive.

Autoscaling matches worker capacity to work; it cures neither a skewed Spark stage nor an unbounded driver, and Spot capacity is cheaper but can disappear. Upgrade a persistent cluster blue-green — build the new one, route new jobs to it, drain the old, delete it — and upgrade an ephemeral fleet by versioning its template and validating it in a lower environment.

5. RPO, RTO, Restore

Pick what went wrong and watch the same five defences sort themselves into the ones that help and the ones that faithfully copy the damage. Like a photocopier next to a fireproof safe: only one of them survives you spilling coffee on the original.

A backup success event proves that bytes were written — nothing more. Only an exercise that restores the data, rebuilds the services, validates permissions and reconciles correctness measures the RPO and RTO you actually have, and it has to run in a location that still satisfies your residency and CMEK requirements. After a failover: prevent split brain, decide how writes return to the original site, and reconcile whatever was created during the event.
