1. Probe Versus Range

Hash Tables: Buckets, Collisions, and Load Factor gave you expected constant-time exact lookup; Hash Map vs Sorted Structure: When Order Matters named the price — the bucket function scrambles key order. Switch the question being asked of a one-million-term dictionary and watch which index collapses. Like a phone book versus a bag of business cards: one name is instant from either, everyone whose surname starts "Rod" is instant from only one.

Order buys more than ranges: nearest key, floor and ceiling, sorted iteration, and the merge-like traversal behind sorted-list intersection. It also buys a worst case — a balanced tree is O(log n) even when a collision-heavy hash table has degraded to linear. You pay in comparisons, node pointers, rotations on every write, and weak locality.

2. Fan-Out Beats Depth

A binary tree minimises comparisons per node — the wrong quantity when block storage hands you whole pages. Widen the node and watch page reads collapse while comparisons barely move. Like a phone tree: calling 2 people who each call 2 takes many rounds; calling 256 who each call 256 reaches a billion in four.

Notice what does not improve: total comparisons stay near log2(n) whatever the fan-out, because you binary-search the separators inside each page. The B-tree does not save comparisons — it saves page fetches, and only fetches are billed. That is the memory hierarchy turned into a shape.

3. A Full Leaf Splits

The unit of rearrangement is a page, not a rotation. Step an insert into a full leaf and watch the separator climb — and see the one move that changes the tree's height. Like a full ring binder: you split the section in two and write one new label on the divider above it.

Occupancy is a real dial: full pages maximise fan-out and leave no insertion room, so splits become frequent — implementations hold a minimum occupancy and reserve space per workload. Sequential inserts create a hot rightmost leaf; random inserts spread the writes but fragment locality. And a B-tree is not an inverted index: it orders whole keys, so it answers equality and range, never term-level containment.

4. Walking A Prefix

A trie stores one symbol per edge, so a prefix is not searched for — it is walked. Tap symbols to descend, and watch the completions narrow while the dictionary size never enters the cost. Like a hotel corridor: you do not check every room, you walk to the right floor and read the doors on it.

A naive trie is memory-hungry: every character may allocate a node holding a map or pointer array, and sparse edges waste space. Path compression collapses non-branching chains into multi-character edge labels — a radix tree — and compact encodings hold edges in arrays rather than heap objects. The prefix mechanics above are unchanged; only the locality improves.

5. Merging Equal Tails

A trie shares prefixes only — mop and top share nothing, because their paths diverge at the first character. Minimise the automaton and the equivalent tails collapse into one. Like two roads that join and run together to the same town: you build the shared stretch once.

The compression is paid for at write time. A mutable trie inserts a path in O(L), but a minimal FST depends on global state equivalence and is built from sorted keys as an immutable artifact — changes land in small mutable overlays or new immutable segments and are merged later, never edited in place. Whatever the representation — bytes, code points, normalised tokens — it must match the analyser, or visually equal strings follow different paths.
