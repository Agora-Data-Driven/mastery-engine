1. Cutoff Is The Threshold

In ML, precision = TP/(TP+FP) and recall = TP/(TP+FN) were computed over a fixed predicted set that a score threshold handed you. A retriever scores essentially every document instead, so there is no set until you cut the ranking at k — and then the same formulas apply, unchanged. Drag the cut. Like judging a bakery by its window display: you have to say how big the window is before "how many are good" means anything.

Two things follow mechanically. Recall's numerator is non-decreasing in k while its denominator R is fixed, so recall can only rise or stay flat. Precision's denominator grows by 1 every step and its numerator only sometimes does, so precision tends to fall. Sweeping k from 1 to the list depth traces exactly the precision–recall tradeoff curve you know from classifiers — the rank cutoff is playing the role of the score threshold.

2. Blind Inside The Cutoff

P@k and R@k are sensitive to rank only across the cutoff boundary, never within it. Tap ranks to place the four relevant documents anywhere in the top 10 and watch P@10 and R@10 refuse to move. Like a taxi that arrives at your door versus one that circles the block five times first — same fare on the meter, very different ride.

Swapping the documents at ranks 1 and 10 changes nothing at P@10. Any metric built from a single cutoff treats the top-k as a bag — membership counted, order discarded. That is not a flaw to patch; it is the definition, and it is precisely the gap average precision exists to fill. Note the one thing that does move as you drag documents across rank 5: the k = 5 pair. Order matters to a cutoff metric only when it carries a document over the line.

3. Choosing k By Consumer

The cutoff is not a convention to memorise — it is a fact about who reads the list. Tap a consumer to see which cutoff and which half of the pair actually decides anything. Like a ladder: the right length is a fact about the roof, not about the ladder.

The asymmetry that decides real architectures: missed recall at the first stage is unfixable downstream, while poor precision there is merely work for the next stage. A reranker can reorder the top 200 all day; it can never recover a document the candidate generator failed to surface. So tune stage one on R@1000 and refuse to be impressed by its precision.

4. Building Average Precision

AP walks the ranking, records precision at every position where a relevant document appears, and averages those values over R. Three relevant documents are pinned at ranks 1, 3 and 5 — drag the fourth and watch AP move while P@10 sits still. Like a race where every runner's finishing time counts, not just whether the team finished.

MAP is the arithmetic mean of AP over the query set, and it is a macro average: a query with 1 relevant document counts exactly as much as one with 50, and queries with zero relevant documents in the judgments are excluded rather than scored 0, because AP is undefined at R = 0. Two cautions. AP assumes binary relevance, so graded judgments must be squashed first and the threshold can flip which system wins. And MAP evaluates to the full depth — commonly 1000 — so it will happily credit improvements at ranks 20 to 50 that no user of a top-5 product will ever see.

5. First Hit Only

Some tasks need exactly one hit — known-item search, navigational queries, factoid lookup, a RAG setup with a single gold passage. RR = 1/r₁ where r₁ is the rank of the first relevant result, 0 if none appears. Drag each query's first hit. Like looking for your keys: finding them in the first pocket you check is worth far more than finding them in the ninth.

One identity ties this panel to the last. If a query has exactly one relevant document at rank r, then R = 1 and the AP sum has a single term: AP = (1/1)·P@r = 1/r = RR. MRR is exactly MAP restricted to single-answer queries, so an evaluation set with one judged passage per query makes MAP and MRR the same number — computing both tells you nothing. And MRR is blind past the first hit: one relevant document followed by nine junk results ties a system returning ten relevant documents, which makes it the wrong metric for research queries, candidate generation, or any RAG prompt reading five slots.
