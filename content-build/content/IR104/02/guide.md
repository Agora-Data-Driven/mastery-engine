**The big idea**: **Precision@k and Recall@k: What Ranking Changes** taught you to cut a ranking and measure the bag above the cutoff. **Average Precision and MAP** taught you a whole-ranking summary that rewards putting relevant documents early. **Reciprocal Rank and MRR** taught you the first-hit metric for single-answer tasks. All three rest on an assumption this lesson removes: that relevance is a yes-or-no bit. Many search experiences need a richer judgment, because a definitive answer, a useful overview and a marginally related page should not receive identical credit. Graded relevance keeps those distinctions, and nDCG keeps them while still rewarding systems that place their strongest results near the top. The second half of the lesson is the choice itself: MAP or nDCG is decided by which relevance model is faithful to your product, not by which metric is more familiar.

**Key concepts**

- **A grade is an ordinal relevance level, not a probability.** The common scale is 0 for irrelevant, 1 for marginally relevant, 2 for relevant, 3 for highly relevant, and instead of counting hits you now sum *gain*. Without grades, a system returning a definitive answer at rank 1 and one returning a tangential mention at rank 1 are indistinguishable to every metric in the previous lesson.
- **Cumulative Gain sums the grades and is blind to order.** For grades `[3, 0, 2, 1]`, `CG@4 = 3 + 0 + 2 + 1 = 6`. Reorder to `[0, 1, 2, 3]` and it is still 6, because addition is commutative. CG recognises graded usefulness and then discards what users care about most: where each grade sits.
- **Discounting repairs that by dividing each grade by a function of its rank.** One common linear-gain definition is `DCG@k = rel_1 + sum from i=2 to k of rel_i / log2(i + 1)`. Rank 1 receives full credit, rank 2 is divided by $\log_2 3 \approx 1.585$, rank 3 by $\log_2 4 = 2$, later ranks by larger denominators — declining attention modelled without pretending everything after rank one is worthless. Because $\log_2 2 = 1$, applying the logarithm from rank one as well gives the identical number, which is why both conventions circulate and both are correct. Worked: `[3, 0, 2, 1]` gives $3 + 0 + 2/2 + 1/\log_2 5 = 4.431$; `[0, 1, 2, 3]` gives $0 + 1/1.585 + 1 + 3/2.322 = 2.923$. Identical CG of 6, very different DCG.
- **Exponential gain is a separate decision layered on top.** `DCG@k = sum from i=1 to k of (2^rel_i - 1) / log2(i + 1)` maps grades 0, 1, 2, 3 to gains 0, 1, 3, 7, so one highly relevant result outweighs several marginal ones. Compare list A `[3, 0, 2]` with list B `[2, 3, 0]`: A scores $7/1 + 0 + 3/2 = 8.5$, B scores $3/1 + 7/1.585 \approx 7.417$. Both hold the same strong documents; A wins purely because the best item is first. Whether that amplification is desirable is a product question — one authoritative answer may be worth disproportionately more in medical or legal search, while several diverse moderate results may serve exploratory browsing better. The gain mapping is a utility assumption and must be documented.
- **Normalization makes DCG comparable across queries.** A query with many highly relevant documents has more attainable gain than one with a single marginal answer, so raw DCG cannot be averaged honestly. `nDCG@k = DCG@k / IDCG@k`, where IDCG is the DCG of the *ideal* ordering — the judged documents sorted by decreasing grade. For list B the ideal is `[3, 2, 0]`, whose DCG is $7 + 3/1.585 \approx 8.893$, so B's nDCG@3 is $7.417 / 8.893 \approx 0.834$. The ideal ordering scores exactly 1, so every query lands on one zero-to-one scale — which is what permits an average across a test collection.
- **IDCG can be zero, and the division is then undefined.** If no judged document for a query has positive relevance there is no ideal gain to divide by. Evaluation code must choose a policy — exclude those queries from the nDCG aggregation, or assign a specified value — and report it. Treating them silently and inconsistently between two runs is enough on its own to change an experiment's conclusion.
- **The cutoff k is part of the metric, not a display option.** nDCG@5 reflects a compact first screen; nDCG@20 values deeper ranking, and a system can improve one while harming the other. Move a grade-3 result from rank 15 to rank 7 by displacing useful results near rank 4, and nDCG@20 rises while nDCG@5 falls. A related surprise: IDCG truncates at the same k, so extending k can *lower* nDCG when the added positions hold zeros while the ideal fills them with gain. Choose cutoffs from the interface.
- **Unjudged is not the same as irrelevant.** Most pipelines score unjudged documents as grade 0, but an unjudged result has not been proven irrelevant. A new system surfacing novel documents is unfairly penalised against systems whose results formed the original judging pool. Deeper pooling and targeted judging of the results that actually changed reduce the bias — mathematical precision does not repair weak labels.
- **Grades need operational definitions, measured agreement and a tie policy.** Assessors must know what separates a 2 from a 3, whether authority and freshness count, and how ambiguous intent is handled; if one calls any topical mention relevant while another requires a complete answer, a score change may be annotation drift rather than ranking quality. Tied predicted scores need a stable secondary key, or repeated runs produce noise that reads like a real ranking change.
- **MAP asks a different question, and it is a good question.** Average Precision assumes binary relevance, averaging precision at the ranks where relevant documents appear and dividing by the number of known relevant documents; MAP averages AP across queries. With two relevant documents, ranking A `[1, 0, 1, 0]` gives $AP = (1 + 2/3)/2 \approx 0.833$ and B `[1, 1, 0, 0]` gives $AP = (1 + 1)/2 = 1$. MAP prefers B for retrieving the complete relevant set with no irrelevant interruption. It rewards coverage and early placement, and every relevant item carries the same value.
- **The disagreement between them is the whole lesson.** Let the two relevant documents have grades 1 and 3. Binary AP is identical whether the grade-3 document sits at rank 1 or at rank 3, since it sees two hits at ranks 1 and 3 either way. nDCG separates them sharply: with exponential gain `[3, 0, 1, 0]` scores $7 + 1/2 = 7.5$ against an ideal `[3, 1, 0, 0]` of $7 + 1/1.585 \approx 7.631$, giving nDCG $\approx 0.983$, while `[1, 0, 3, 0]` scores $1 + 7/2 = 4.5$, giving nDCG $\approx 0.590$. Same AP; nDCG differs by a factor of 1.7.
- **Choosing by relevance model is the actual skill.** MAP is faithful where relevance is meaningfully yes or no and retrieving the complete set matters: documents responsive to a narrow legal request, every known duplicate, all eligible records for later review. nDCG is usually faithful for web search, recommendations, help centres and other ranked experiences where usefulness varies — a direct answer at grade 3, a supporting page at 2, a tangential result at 1 — and cutoff and discount can be tuned to attention at the top of the interface. Start from the product's relevance model, never from the metric you already have code for.
- **Neither metric captures all product value.** MAP does not express graded utility; nDCG applies little pressure to find every relevant item when k is shallow. Neither measures novelty, diversity, latency, trust or task completion — a recommender showing ten near-identical highly relevant items can post excellent nDCG and a poor experience.
- **Label quality can decide the metric for you.** Graded judgments demand assessors who reliably distinguish levels. If agreement between grades 2 and 3 is poor, exponential gain amplifies that noise — the gap between those grades is 3 versus 7. Collapsing uncertain grades to binary and using MAP can be the more stable signal despite losing nuance; the alternative is to improve the rubric and test metric sensitivity under plausible label changes.
- **Aggregation hides behaviour; per-query results are the cure.** Both MAP and mean nDCG weight every query equally regardless of traffic, so report macro averages alongside traffic-weighted summaries and per-query deltas. Testing operates on per-query *differences* — a move from mean nDCG 0.52 to 0.53 is evidence only once you know whether it is broad or driven by a few queries.

**Rules to remember**

- CG is order-blind; DCG adds position; nDCG adds cross-query comparability. Each layer fixes one defect.
- The ideal ordering scores 1 by construction, so a positive IDCG bounds nDCG in $[0, 1]$.
- IDCG comes from the judged documents sorted by grade, truncated at the same k as DCG.
- Zero IDCG is a policy question. Choose it, document it, apply it to every run.
- Grade scale, gain transform, logarithm convention, cutoff, zero-IDCG policy and unjudged policy must all be recorded, or two dashboards labelled "nDCG" compute different quantities.
- AP and MAP are binary metrics. Graded labels must be squashed first, and the threshold you squash at can change the winner.
- nDCG sees degrees of gain and rank-sensitive utility; MAP sees set coverage and interruption. Pick by relevance model.

**Common pitfalls**

- **Treating CG as a ranking metric.** It sums grades and reordering never moves it — `[3, 0, 2, 1]` and `[0, 1, 2, 3]` both give 6.
- **Comparing raw DCG across queries.** Queries have different attainable gain; that is what normalization removes.
- **Assuming one nDCG.** Gain transform and cutoff are choices; changing either moves the number with no ranking change.
- **Letting IDCG = 0 fall through as a divide-by-zero, a NaN or a silent zero.** All three corrupt the mean differently, and invisibly.
- **Reading unjudged as irrelevant.** It penalises systems retrieving documents outside the original pool — usually the new one.
- **Using exponential gain on noisy labels.** If assessors cannot separate 2 from 3, the transform amplifies the disagreement, not the signal.
- **Choosing nDCG because it looks more sophisticated.** On a binary task with a coverage requirement, MAP is faithful and nDCG is the wrong abstraction.
- **Selecting the metric, or the squashing threshold, after seeing the results.**
- **Reporting a mean with no per-query distribution.** A 0.01 gain can be broad or can be three queries.

**How to approach the questions**

1. For DCG arithmetic, write the denominators first — $\log_2 2 = 1$, $\log_2 3 \approx 1.585$, $\log_2 4 = 2$, $\log_2 5 \approx 2.322$ — then decide whether the gain is linear or exponential. Many wrong answers are the right formula with the other gain mapping.
2. For nDCG, build the ideal list explicitly: sort the grades descending, truncate at k. Distractors use the full-list IDCG or forget to truncate.
3. When two systems tie on AP or MAP but differ in quality, the answer involves graded relevance and position.
4. When a question changes only the cutoff, expect the metrics to move in opposite directions, and check whether IDCG changed too.
5. For "which metric" questions, identify the relevance model: complete-set retrieval with yes/no labels points at MAP, varied usefulness with a top-heavy interface at nDCG.
6. Watch for claims that a metric guarantees user value. Diversity, novelty, latency and task completion sit outside both by construction.
