Notice what every right-hand lever charges: extra model calls and latency. That is the only currency in this lesson, and the judgment is never "is this technique good" but "does this traffic deserve to pay". A rewrite costs 100–300 ms and is nearly always worth it; a three-iteration agentic loop costs ten seconds before generation even starts and is worth it for almost nothing.

2. Four Ways To Rewrite

Four transforms that all end in the same place — a different string goes to the index than the one the user typed. Switch between them and watch the query change and the bill change with it. Like translating a question into the language the archive was written in, before you ask it.

All four are pre-retrieval, and the first three are stateless, which is why they are trivial to A/B against the raw query. Order of adoption in a real system: rewriting first, expansion only when recall is measurably short, HyDE for conceptual traffic only — and always log the original query so a transform that degrades results can be switched off without losing what the user typed.

3. Search, Read, Stop

The model holds the search tool and calls it in a loop. Press search again and watch the three stop signals move — coverage, marginal utility, budget. The hard part is not searching. Like a researcher who has to decide when the reading is enough, with the clock running.

Tool design carries the reliability: stable document IDs in snippets so read is cheap, filters in the tool schema so the model can scope its own searches, identical searches cached within a session, and the whole trace recorded — when an agent goes wrong, the sequence of queries it issued is the primary debugging artifact, and nothing else in the log explains the answer.

4. Hops Multiply

Compositional questions are answered by chaining facts, and chains multiply. Drag the per-hop success rate and the number of hops, and watch the end-to-end number fall faster than intuition says it should. Like a relay race: every runner is excellent, and the baton still gets dropped.

Two judgments follow from the arithmetic. Decompose only genuinely compositional questions — comparisons and bridging-entity chains — and try a single retrieval first for anything simpler. And evaluate per-hop retrieval success separately from final answer accuracy: one end-to-end number cannot tell you which hop leaked, and the fix for a retrieval miss is not the fix for a decomposition that split the question along the wrong joints.

5. Gates And Guardrails

Two places a system refuses to trust model output: the gates that check a RAG answer, and the guardrails around generated SQL. Toggle each one off and watch what gets through. Like a kitchen pass: someone looks at every plate before it leaves, and nobody is offended.

The common rule: a check is a model judgment, so it needs a budget, and generated SQL is never executed raw. Allow one or two re-retrievals, then answer with explicit caveats or abstain — for a support product, I could not verify this from our documentation beats a fabricated policy detail every time. And log which corrective path fired per request: the distribution of those flags is the health metric of the retrieval layer underneath.
