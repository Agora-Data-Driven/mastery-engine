2. The Pre-Generation Wall

Streaming hides decode behind progressive rendering. It hides nothing before the first token — that block is dead time, and it is the only part engineering really controls. Toggle the stages and watch the wall move. Like a kitchen: the diner forgives a long meal, never a long wait before the first plate.

Two expert habits behind this picture. Measure p50 and p95 in production — benchmark numbers lie about queueing, which is exactly where the tail lives. And give every stage a deadline with an evaluated fallback: a reranker timeout serves the fused order, a model timeout retries once then degrades gracefully, and queues stay bounded so overload sheds load instead of compounding it.

3. Where Caches Cut In

Three caches sit at three points of the same chain. Each saves more than the one before it — and each is more dangerous than the one before it. Pick a layer, then drag its hit rate. Like keeping leftovers: the further along the cooking you saved it, the more time you get back and the sooner it goes off.

Caching is the cheapest capacity available, and every layer is a consistency liability. So hit rate and staleness complaints are read together, never separately: a rising hit rate alongside rising stale-answer reports is a failure mode wearing a success metric.

4. What The Key Carries

A cache is only as correct as its key. Every version that can invalidate an entry has to be in the key, or the cache keeps serving something that was true once. Switch a component off and read what breaks. Like a filing label with no date on it — you will happily pull last year's contract and never notice.

Some things are never cached at any key: personalized answers, answers derived from revoked documents, and time-dependent facts such as a status page. The test is not "does this repeat?" but "if the world changed, would this entry be wrong and would anyone find out?"

5. Stuff It Or Search It

Million-token windows invite a shortcut: skip retrieval, stuff the corpus into the prompt. The comparison deserves numbers rather than vibes — because one path pays the corpus cost once and the other pays it on every query. Like buying a book versus paying the full cover price each time you want to check one page.

The closing judgment of the course: retrieval was never a workaround for small windows. It is a cost, latency and attention-precision optimization whose logic survives infinite windows, because feeding the model everything means paying to attend to mostly noise. Bigger windows move the break-even point; they do not repeal it.
